# 03. 世界とシステム

## 1. 自由度の構造：立場 × 職業 ＋ 人生目標

生き方の自由を、2つの独立した軸で作る。

| 軸 | 意味 | 例 |
|---|---|---|
| **立場** | **何ができるか**（入れる場所、会える人、受けられる依頼）。戦闘力は与えない | 流れ者 → 市民 → 冒険者ランク / 騎士・貴族 / 聖職 / 商会 |
| **職業** | **日々何をするか**（主に使うスキルと、勝負所で出るミニゲーム） | 鍛冶師・商人・採掘師・薬師・密偵・吟遊詩人・冒険者 |

- 2軸は独立に動く。鍛冶師のまま叙爵される、商人から錬金術師へ、なども起きる
- **認定**：職業や立場は「選ぶ」ものではなく、条件を満たすと打診が来る。条件は経歴フラグ＋実績の論理式（JSONで書き、zodで検証する）
  - 例：`鍛冶師認定 = 鍛冶 ≥ 20 ∧ 納品した作品 ≥ 3 ∧ 師匠の紹介`
- **人生目標カタログ**：周の序盤に人生の目標を宣言できる。宣言は縛りではなく、達成時に報酬が増えるだけ。途中で変えてもよい（ペナルティは軽い）
  - 画面に出すのは**「いま手が届く目標3つ」だけ**。達成したら入れ替える
  - カタログにない道も、条件式を満たせば開く（カタログは入口で、自由は条件式の組み合わせで担保する）
- 分岐の入口は、依頼・事件・出会いのイベントテーブル（条件 → 効果）
- **NPCの態度の変化**で成り上がりを見せる：門番やギルド受付の台詞が、立場・名声で変わる（`voices.json` のテンプレート差分）

## 2. ミニゲーム基盤

### 使い所の原則（最重要）
ミニゲームは**「毎回やらされる作業」ではなく「ここ一番の勝負」**として出す。数を多くしても、使い所を外すと作業になる。

- **日常の行動は簡易判定**：いつもの鍛冶仕事や普通の採掘は、スキル値で即座に結果が出る（ミニゲームなし）。遊びたければ手動でも遊べる
- **勝負所でミニゲームが出る**：
  - 特別な注文、品評会、コンテスト（鍛冶・料理・演奏）
  - 交渉・説得の山場（大きな取引、仲間の勧誘、裁判）
  - 決闘・一騎打ち、因縁の相手との勝負
  - 大金が動く真贋鑑定、賭場の大勝負
  - 隠し条件やユニークシナリオの鍵になる場面
- **勝負所の結果は物語を動かす**：取引の成否、評判、立場の変化、ルートの分岐。数値が増えるだけでは終わらせない
- 頻度の目安：1日（約15分）に1〜2回。同じミニゲームが続かないよう、イベントテーブルで間隔を空ける
- 大きな成長（ティア更新）と、称号・世界初は勝負所で起きる

### 共通の型（コストを抑えて数を増やす）
すべてのミニゲームを、純TSの1つの型にそろえる。

```ts
interface MiniGame<Input, Result> {
  init(ctx: { skills; materials; order; seed }): State
  tick(state: State, input: Input): State   // 固定タイムステップの状態機械
  result(state: State): Result              // → 作品（品質・ティア・特記フラグ）
  autoplay(ctx): Input[]                    // 簡易判定＝入力列の自動生成
}
```

- 入力列のリプレイ、シード固定のテスト、簡易判定が、この1つの仕組みで成り立つ
- **入力の型は3種類**。新しいミニゲームは「見た目とデータを替えた別の皮」として追加する

| エンジン | 入力 | 皮の例 |
|---|---|---|
| タイミング | 判定窓に合わせて押す | 鍛冶、演奏、釣り、居合（決闘） |
| 盤面推理 | マスを開ける・並べる | 採掘（マインスイーパー風）、鑑定、錬金 |
| 駆け引き | カード・選択 | 交渉・口論、賭博、料理、指揮（合戦） |

### スキルの効き方：勝率の倍率にせず、操作を助ける
上手い人は低スキルでも突破できる。スキルは「快適さと上限」を買うものにする。テストは `判定窓 = f(skill)` の純関数で書ける。

| ミニゲーム | スキルが上がると |
|---|---|
| 鍛冶 | 「良」の判定窓が広がる。Lv20で最適温度帯が見える。Lv40で打つ順番の候補が光る。派生スキルで失敗を1回取り消せる |
| 採掘 | ヒントの範囲が広がる。中級で鉱脈の種類が色で出る。上級で1回だけ安全マスを確定できる |
| 交渉 | 手札の上限と、相手の次の論点の予告数が増える（戦闘の予兆システムと同じ仕組み） |

### アクション系の扱い
- 「3秒以内に終わる一点勝負」に限定する（居合の間合い、背後からの接近）
- 判定はフレームでなく**時間ベースの数値窓**（例：±80ms）で、`balance.json` に置く。設定で窓を広げられる
- ヘッドレスで「完璧な入力なら満点、無入力なら失敗」を自動検証する
- **手触りはオーナーが触って数値で返す**レビューを必ず挟む（Devinには判断できない）

### 作業化を防ぐ
- 成長が大きく伸びるのは**ティアを更新したときだけ**（02 §2）
- 同じ品を売り続けると相場が下がる（収益にも反復減衰）
- 毎回変わる**注文**（依頼主の条件：硬さ・色・納期）を付ける。同じ解き方が通用しない
- 日替わりの要因（天候・相場・客の機嫌）は**2つまで**
- 熟練すると問題の種類が増える（Lv30で合金、Lv50で銘打ち、など）
- 失敗にも面白い結果を用意する（珍品、呪いの剣）
- **簡易判定**（日常の行動、または勝負所を手動で遊ばない場合）：品質は直近5回の中央値の80%、経験は50%。称号・世界初・会心は手動で遊んだときだけ出る

## 3. 作品台帳（すべての記録の元）

ミニゲームの結果と偉業を、同じ形式で1件ずつ記録する。

```ts
type Work = { id; kind; maker; quality; tier; order; flags; day; worldSeed }
```

成長（ティア更新の判定）、称号、新聞、年代記、転生の遺物は、すべてこの台帳を読む。
新聞やNPCの台詞の差分は、台帳の記録から機械的に生成できる。

## 4. 戦闘：予兆を読むCT制ターンバトル

- tick単位で時間が進む。行動ごとにCTがあり、敏捷や武器の重さで変わる
- 敵は大技の前に**予兆**を出す。予兆の表示は固定3行で、《観察》が上がると中身が正確になる
  - 観察が低い：「狼が唸っている」
  - 観察が高い：「狼が後ろ足に重心を移した――**飛びかかり**（2tick後）」
- 敵の行動パターンは固定ルールで書く。プレイヤーが学習できる
- 部位（頭・胴・腕・脚）へのダメージは怪我として数日残る
- 死亡時は教会で蘇生する。代償として未定着経験の50%と所持金の一部を失う。数値は下がらない。死は年代記に残る

## 5. 世界

- MVPでは**手作りの世界1つ**。ユニークモンスターと隠し要素の出現だけをシードで抽選する
- 隠し要素は、時刻・天候・月齢・状態・所持品の組み合わせで出る。**見逃し対策として、必ず噂のヒントを置く**。周回ごとに条件のパラメータ（場所・時期）を変える
- **噂・新聞**：作品台帳と世界の出来事から、テンプレートで1行生成する（状態は持たない）。勘違い系の見出しを混ぜる
- **ライバルとランキング**：ランキングの数値は乱数で動かす。ネームドのライバル数人に口調を持たせる（MVP後）
- 時間：1日は行動3〜5回で約15分。曜日・季節・月齢がある

## 6. 通知予算（快感を薄めない）

| ランク | 例 | 頻度 |
|---|---|---|
| **S** | ユニークスキル、認定職の打診、世界初、立場の上昇 | **1セッションに1回以下** |
| **A** | 派生スキル、珍しい称号、ティア更新 | 1セッションに数回 |
| **B** | 通常の称号、スキルのランクアップ | ログにまとめて折りたたむ |

- S候補の条件に近づいたら、条件を明かさずに一行だけ出す：`――何かが、噛み合いかけている。`
- 新規性の供給スケジュール（`balance.json` の `noveltySchedule`）：15分・1時間・3時間・8時間の各時間帯に、初体験イベントが最低N件起きること。`pnpm sim:retention` で検証する

## 7. 称号・条件のDSL

```jsonc
{
  "id": "title.hundred_wolves",
  "name": "百狼斬り",
  "rank": "B",
  "condition": { "counter": "kill.species.wolf", "gte": 100 },
  "effect": { "damageVs": { "wolf": 1.05 } },
  "message": "――称号《百狼斬り》を獲得しました。"
}
```

- 演算は `counter / flag / skill / stat / work(台帳) / time / and / or / not / within`
- 称号を量産すると似たものばかりになるので、**先に「条件の型」を10種ほど設計し**、型ごとに数を増やす。人間が1割だけ磨く

## 8. 年代記

- 偉業・死・失敗・作品を、物語として残す（「負けることも楽しい」）
- **セーブとは別の領域・別のバージョン**で保存する。周回をまたいで持ち越す（`06_endgame.md`）
