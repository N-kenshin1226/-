# 10. 世界の広さ（シードごとの地方・町・地域・ダンジョン）

## 1. 問題（2026-10-28 時点）
- 町は2つ（アルディ・ベルン）、街の外の地域は5つ（森・旧街道・湖畔・開墾地・深層の穴）、敵は14種
- どのシードでも**同じ地図**。「シードごとに違う世界」（`08_world_crisis.md`）になっていない
- 一生（約40年）と転生を遊ぶには、行ける場所・会える人・戦う相手が足りない

## 2. 方針
- **世界（地方）はシードから生成する**。町・地域・ダンジョンを「型」から組み立て、配置・名前・特産・人・敵・危機との関わりをシードで変える
- 型は手で作り込む（質のため）。組み合わせと配置で量を出す
- 少数の**名所**（特別な場所）は手作りで、シードで現れたり現れなかったりする
- 遠い場所ほど危険で、行くには腕・装備・立場・旅の備えが要る。**世界が段階的に開けていく**こと自体を楽しみにする

## 3. 規模の目安（1つの世界）

| 種類 | 数 | 型の例 |
|---|---|---|
| 町・村 | 6〜9 | 宿場街、港町、鉱山町、城下町、農村、学術都市、辺境の砦、聖地、隠れ里 |
| 地域（野外） | 15〜25 | 森、深い森、丘陵、山岳、湖、川、海岸、湿地、荒野、雪原、火山、古戦場、廃村、遺跡の野 |
| ダンジョン | 5〜10 ＋深層 | 洞窟、坑道、地下墓所、古代遺跡、魔物の巣、塔、沈んだ神殿 |
| 名所 | 2〜5 | 手作りの特別な場所（hidden） |
| 敵 | 型 60〜80 × 地域の変種 | 獣、人、不死、魔物、精霊、竜種。地域ごとの亜種（雪原の狼、火山のトカゲ…） |

## 4. 町
- 型ごとに、持っている**場所**（鍛冶場・市場・港・坑道・図書館・闘技場・神殿…）、**特産**（相場の安い品・高い品）、**住人**（師匠・ライバル・依頼人）、**注文と出来事**の傾向が違う
- 町同士の相場の差が、商いと旅の理由になる
- 町ごとに立場・評判を持つ（ある町では有名、別の町では無名）

## 5. 地域（野外）
- 生物群系（森・山・海…）ごとに：採集できる物（季節・天候で変わる）、敵、発見（`discoveries.json`）、背景の情景
- 地域の中に**小さな地点**を数個持つ（泉、炭焼き小屋、見張り塔跡、獣道…）。散策・採集・野営・出来事の舞台
- 危険度は、始まりの町からの距離と地形で決まる

## 6. ダンジョン
- 型（洞窟・墓所・遺跡…）から、階層・部屋・罠・宝・主（ボス）を生成する
- 1回で攻略しきれない深さ。野営と撤退の判断がある
- 主の一部はユニークモンスター（世界に1体。世界初の対象）
- 既存の「深層」は、いちばん深い無限ダンジョンとして残す

## 7. 旅
- 地方の**地図**：町と地域が道でつながる。道には日数・危険度・関所・季節で閉ざされる道がある
- 移動は日数を使い、道中で出来事・野営・遭遇が起きる。隊商に同行する、馬（騎乗）や船（港町）を使う、などで速さと安全が変わる
- 行ったことのない場所は地図上で霧がかかっている（噂・新聞・地図の購入で明らかになる）

## 8. 見た目
- 背景は「情景の部品」（空・遠景の山・中景の建物や木・前景・灯り）を型ごとに組み合わせて作る。時間帯と天候を重ねる
- 町の型・地域の型ごとに、配色と部品の組み合わせを持つ。同じ型でもシードで配置が変わる

## 9. 危機・物語とのつながり
- 危機（`08_world_crisis.md`）の影響は地方の地図に出る：閉ざされる道、荒れる地域、人が去る町、危機の中でだけ行ける場所
- 物語のアトム（`07_story.md`）は、町・地域・ダンジョンの型に結びつけて置く（シードで配置が変わっても破綻しないよう、参照は型と役割で書く）

## 10. 検証（sim）
- 1000シードで、地方が必ずつながっている（行けない町がない）
- 序盤の町の周りに、危険度の低い地域が必ずある
- 遠くの地域は、序盤の能力では危険すぎる（段階的に開ける）
- 生き方ごとのボットが、一生のうちに地方の大半を訪れる

## 11. 実装メモ（G-01・G-02・G-04 完了時点）

### できたもの
- **町の型9種・地域の型16種**（14種＋特殊な「開墾地」「深層の穴」）を `packages/content/world.json` にデータとして定義（zod 検証付き）。場所・特産（市場の安い品/高い品）・住人（宿屋の主・門番…）・師匠・掲示依頼・採集・敵・散策表・地点の傾向が型ごとに違う
- **`generateWorld(seed, file, cfg)`**（`packages/core/src/world/`）：町 6〜9・地域 15〜25 をシードから決定論的に生成。町は道でつながるグラフ（全町連結＋輪ごとに追加の道）。始まりの町 `t0` からの輪（BFS距離）で危険度が上がり、近くは安全。全町に地域が1つ以上＋始まりの町に開墾地・最遠の町に深層の穴が必ずある
- **生成されるもの**：町の場所（門・宿の自室・宿屋・酒場・市場・広場・集会所・教会・鍛冶場 −omit ＋型固有）、地域の場所（狩り・採集・散策・地点・仕事・深層）、住人・師匠・掲示依頼・市場（基本＋型の品揃え＋町ごとの揺らぎ・特産の値引き/値上げ）・敵（危険度の蓋で絞った2〜3種）・地点（型の出やすい表から1〜3個）
- **町ごとの評判**（`life.rep`）：依頼・仕事・寄付で上がり、相場に効く（buy/sell の係数。上限と効きは `balance.world.rep`）
- **地点**（spot）：地域の中の小さな場所。`{type:"spot"}` コマンドで型の出来事表から1件引く（泉の水・祠の祈りなど）
- **行動の一般化**：散策・採集・旅・市場・依頼など P-02 の行動は固定の場所 id ではなく、場所の町・型の表（`LifeConfig.towns/places/spots/stroll` の型別キー `town.<型>`/`region.<型>`）から引く。生成地方では生成の寄与分で営みの表を差し替える（`apps/web/src/world.ts` → `cfgFor(state)`）
- **セーブ v20**：`GameState.world = { kind: "legacy" | "gen", recipe }` と `life.rep` を追加。旧セーブは `world.kind="legacy"`・`rep={}` に移行され、固定マップ（アルディ・ベルン）の世界としてそのまま遊べる
- **解決層**：`worldFor(state, worldFile, balance.world)` が gen なら seed から再生成、legacy/旧セーブなら null（固定コンテンツのまま）。web は `apps/web/src/world.ts`＋`cfgFor(state)` 経由で場所・町名・人名・師匠・敵・営み表を引き、画面は地図の出所を意識しない
- **新しい周は生成地方が既定**（`?world=legacy` で固定マップを選べる互換経路。e2e は全件 `world=legacy` で回し、生成地方は `worldgen.spec.ts` が煙テストする）
- **敵 roster**：地域の型ごとの敵を `enemies.json` に追加（旧3エリア＋13型・計約40種）。生成地域の敵は危険度の蓋で絞る（`dangerChallengeBase + danger×per`）
- **図鑑の拡張（G-04）**：基本種は71（獣・人・不死・魔物・精霊・竜種の6系統、`family` フィールド）。獣は従来の `beast` 旗をスキーマが自動で立てる（beast.attack / beast.exp はそのまま）。系統は使用記録の `foe.<family>` タグに刻まれる
- **バイオーム別亜種**：`enemies.json` の `biomes`（地域型 → 接頭辞・係数）× `variants`（基の種 × 適応先）をスキーマのローダーで `<基>__<バイオーム>` に展開（雪原の大狼・火山の岩蜥蜴など15種）。亜種は型・行動・戦利品を継ぎ、名と数値だけが地方の姿になる
- **撃破の戦利品**：敵ごとの `drops`（品・確率・個数）を `step` が世界シード×敵×撃破序数の独立乱数列で決定的に引く（`itemGot` イベント。深層の撃破も同じ抽選）。戦利品は料理（焼き獣肉）・町の依頼（革・霊質・魔晶石の納品）・市場の売却へ流れる
- **生物群系の素材**：地域型の採集表に biome 固有の品を追加（火山の火炎石・雪原の氷晶石・湖畔/河/海岸の真珠・沼の霊質など15種）

### 決定論と検証
- 生成は world seed と `WORLD_RECIPE`（版）だけから引き直す。セーブには刻印だけを載せ、地図の中身は保存しない
- 単体テスト：同一シードの再生成一致・別シードの変化・1000シードでの個数/連結/町あたり地域≥1・安全帯と危険度の段階・全参照（場所・道・敵・品・NPC・師匠・依頼・地点）の正当性・敵の蓋
- e2e：`worldgen.spec.ts` で生成地方の開始・門から地域への移動・散策・シード決定論を検証

### G-02（地方の地図と旅）
- **道の強化**（`world/`）：生成の道グラフの各辺に種別（街道 `highway`・山道 `mountain`・海路 `sea`）・危険度・関所料金・季節の通行止め・敵表を畳む。道の安定 id は from/to を昇順に並べた `journeyIdOf`（双方向の同一視。遭遇の乱数列・危機の closeRoads・地図のキーに使う）
- **旅の状態**（`life.journey = { to, daysLeft, from, way, road }`）：`journey` コマンドで出発し（1行動・料金＝運賃＋関所料）、野営（`rest`）で残り日数が進み、0 の朝に着く（`journeyArrived`）。旅の途中は町の画面へ戻れない（web 側も街道の窓に誘導する）
- **通い方**（徒歩・隊商・騎乗・船）：`journeyWaysOf` が道の種別で使える方を返す（海路は船のみ・陸路に船は出ない）。料金・実効日数・遭遇係数は `balance.life.journey.ways`。馬・船は将来の乗り物拡張の鈎として既に機能する
- **道中の遭遇**：街道の散策ごとに `road.danger × encounterPerDanger × 通い方の係数` で決定的に抽選（1日1回まで、`roadEncounterDayKey` で抑止）。遭遇したら web は同じ引数で先読みして戦いの場面へ進める
- **地図の霧**：`life.map = { visited, heard }`。訪れた町の隣町と属する地域は刻印なしで名が知れる（`mapKnownSet` で導出 —— 常識として伝わる噂）。遠い町は「？」の輪郭だけ。晴らす経路：到着（`markVisited`）・噂/朝刊（`revealPick` が seed×日×通し番号で未知の場所を1つ選ぶ。町に居る眠りで `newsRevealChance` 抽選）・地図の購入（`reveal:"map"` の品《地方の地図》を市場で買う → `markAllHeard` ＋ `mapRevealed`）
- **季節・危機の閉鎖**：`roadSeasonClosed`（道ごとの closedSeasons）と `crisisRoadClosed`（危機の段階影響 `closeRoads` が道 id か種別で封じる）で出発を止める。閉ざされた道は地図に破線＋✕、荒れた地域は ⚔ の印（`crisisAreaClosed`）
- **地図画面**（`apps/web/src/screens/map.tsx`）：町・道・地域を % 座標で描く見取り図＋旅の列。門の「地方の地図を開く」行動・見取り図の M キーで開く。生成地方・固定マップの両方で動く
- **セーブ v22**：`life.map` と journey の `from/way/road` を追加。旧セーブは v22 移行で `map={visited:[基点],heard:[基点]}`・journey=null に補われ、固定マップの旅（アルディ↔ベルン）は従来どおり動く
- **sim**：`withTravel` が生き方ボットに旅欲を混ぜる（未踏の隣町へ旅立ち・未踏の地域へ出る・閉鎖と関所料は選ばない）。4生き方ボットが 2年で町の6割・町＋地域の5割以上を訪れることを `bots.test.ts` で検証
- e2e：`worldgen.spec.ts` に地図→旅の1本を追加（霧・旅日数・道中の出来事・野営・遭遇→戦闘・到着）

## 12. 実装メモ（G-05 完了時点）

### できたもの
- **情景の部品**：背景を層（空・遠景・中景・前景・灯り・空気）の組み合わせで描く仕組み。部品（山稜・家並み・樹列・坑口・船・遺構…約50種・形違いのバリアント付き）・配色（17種の色票。影3色・アクセント・雪・水面・空気の霞・空の差分）・型ごとのレシピを `packages/content/scenery.json` にデータとして定義（zod 検証付き）
- **型ごとのレシピ**：町の型9種・地域の型17種（16型＋街道）・深層3型（深層・洞窟・墓所）。レシピは各層の配置項の列で、項は部品・個数（固定または範囲）・足場（x範囲・基線y・y揺れ・拡縮・反転・形の指定）を持つ。町のレシピは `places` に場所ごとの差分を畳める（門なら門と壁、市場なら露店…）
- **配置はシードから決定的**：`apps/web/src/ui/scenery.tsx` のレンダラが `createRng("<世界seed>:scenery:<場所>")` の項ごとの系列から置き方を引く。同じ世界シード・同じ場所なら必ず同じ情景、別の世界では配置が変わる。`Math.random` は使わない
- **解決層**：`apps/web/src/scenery.ts` の `sceneryForScreen(state, screen, lastPlace)` が画面と場所からレシピを引く（町の場所→町の型＋場所差分、地域→地域の型、深層画面→ダンジョン、旅→街道）。屋内の場所（鍛冶場・酒場・ギルド・教会・宿屋・自宅）と読みもの用の画面は null を返し、従来の固定背景（SceneBackground）に倒れる —— 画面側は `sceneOf` と同じ規則で引く
- **時間帯・天候・危機**：レンダラは SceneBackground と同じ色票（PALS）・天候の層（WeatherLayer）・危機の霞（haze）を重ねる。深層（`sky:false`）は空・星・天候を描かず地下の闇になる
- **legacy 互換**：`scenery.legacy` の当て方で固定マップの町・地域を型のレシピに写す（アルディ→宿場街、ベルン→港町、森→森、旧街道→街道、深層の穴→深層…）。`?world=legacy` と旧セーブは型の情景で描かれ、屋内は従来の部屋の情景のまま
- **確認用の窓**：`?scn=<town|region|dungeon>.<型>` で1枚、`?scn=all` で全型の一覧。`?tod=`/`?weather=`/`?seed=` で条件を変えられる（e2e と見た目の確認用。ゲーム本体は動かさない）
- **GameState 不変**：情景は描画だけの差分で、セーブに何も載せない（世界の刻印 seed×recipe から毎回同じ情景を引き直す）

### 決定論と検証
- 配置は世界シード×場所 id から `createRng`/`fork` で引く。セーブ・リロード・時間帯で配置は変わらない（tod/weather/haze は描画の重ね層）
- 単体テスト（`apps/web/src/scenery.test.ts`）：layoutEntry の同一系列一致・別系列の変化、全型→レシピの網羅、legacy 当て方、屋内/固定背景への倒れ、同一 seed の描画一致、時間帯・天候・危機の層
- コンテンツ検証（`check:content`）：scenery.json のスキーマ＋部品・配色・町/地域/ダンジョン・legacy の当て先の相互参照（world.json の型と places.json の地域を実在するレシピに結ぶ）
- e2e（`apps/web/e2e/scenery.spec.ts`）：`?scn=` の全型スクリーンショット（`e2e/artifacts/scenery-*.png`）・一覧・時間帯×天候・シード決定性・生成地方の場所/地域の `data-scenery`・legacy の当て方・375px 幅

## 13. 実装メモ（G-03 完了時点）

### できたもの
- **有限迷宮の型7種**（洞窟・坑道・地下墓所・魔物の巣・古代遺跡・塔・沈んだ神殿）を `packages/content/world.json` の `dungeonTypes` に定義。型ごとに危険度・名の表・説明・敵表・罠表・宝表・主の表・主の称号・ユニークの名を持つ。罠は `trapKinds`（難しさ・疲労・灯りロス・踏んだ/躱した文）として別表
- **`generateDungeons`**（`packages/core/src/dungeon/`）：個数（5〜9）・型（1世界2まで・輪の危険度で蓋・始まりの町に必置）・階層（危険度ほど深い、3〜6層×2〜4室）・部屋（戦闘6:罠1:宝1）・宝・主を専用系列 `rng.fork("dungeons")` から決定的に生成。生成は world seed×recipe から引き直すので GameState に迷宮の中身は載せない
- **主とユニークモンスター**：最奥の主は型の表＋《称号》で出る。全迷宮のうち1つだけ主がユニークモンスター（危険度≥`uniqueBossMinDanger` のものから重み抽選）で、生成名と強化係数を持つ。討伐は `bossDefeated` イベント→報せ（通常A・ユニークS）と記録に
- **潜りと進行**：step の `dungeon` コマンド（G-03）。1回の潜りは `diveCost`=2行動。灯り（`lightPerDive`=12）は部屋ごとに1＋踏んだ罠の分だけ減り、尽きるか主の間を抜くと潜りが閉じる —— 灯りが尽きるより先に出る「引き上げ」が判断になる深さ（大半の迷宮は1潜りで抜き切れない）。進行は counters/flags に刻む：`dg.rooms.<id>`（抜いた室数・主の間含む）・`dg.cleared.<id>`（制覇）・`dg.dives`（潜った回数）・`dg.camp.<id>`（野営した日）・`dg.unique.<id>`/`dg.unique`（ユニーク討伐）
- **迷宮内野営**：潜りを `end:"camp"` で閉じると迷宮の中で眠り（`{type:"sleep",camp:true}`、眠りの質は `dungeons.campQuality`=0.45 で街道より浅い）、翌日その迷宮への潜りは行動を要さない。野営の刻印は1回の無償潜りで消える
- **罠**：部屋の罠は観察の技能値と難しさから回避率を畳み、世界シード×迷宮×部屋×日の系列で決定的に見破る（`rollTrap`）。踏むと疲労と灯りロス
- **敵の強化**：部屋の敵は層に応じて HP・威力・挑戦差・敏捷が伸び（`scaleRoomEnemy`）、主はさらに boss 係数、ユニークは unique 係数が乗る（`bossEnemy`。`uniqueVariant:true` で図鑑・個体抽選は「その1体」扱い）
- **世界への組み込み**：`generateWorld` が `WORLD_RECIPE` v3 で迷宮を生成（追加は専用系列なので町・地域・人・道の生成は v1 と同じ結果）。迷宮は `kind:"region"` の場所（袋小路、`潜る`＋門へ戻る行動のみ）として門の「街の外」に並ぶ。`lifePlaces` の型は `dg.<型>` —— 情景は `dungeon.<型>` のレシピを引く
- **情景**：scenery.json に有限迷宮7型のレシピを追加（深層3型＋7型＝ダンジョン8レシピ）。迷宮の場所と潜りの画面はその迷宮の型で描かれる
- **画面**：場所の行動「迷宮に潜る」→ 探索画面（`screens/dungeon.tsx`）。部屋を順に開き、戦闘は深層と同じ戦闘画面の部品、罠・宝は即座に解決、灯りゲージと進行を出す。「先へ進む／野営する／引き上げる」で潜りを閉じ、結果を `dungeon` コマンドに畳む。記録画面に迷宮の欄、新聞・報せ・起床文に主の討伐と制覇が出る
- **GameState 不変**：進行は counters/flags に載せたのでセーブの版は迷宮では据置（地図の G-02 で v22 済み）

### 決定論と検証
- 生成は `rng.fork("dungeons")` の独立系列 —— 同じシードなら同じ迷宮群、かつ迷宮の追加で町・地域の生成結果は変わらない（v1/v2 の差は迷宮とレシピ版だけ）
- 単体テスト（`core/src/dungeon/dungeon.test.ts`、22件）：生成の決定性・全7型・階層/部屋の範囲・ユニーク1体・主と部屋敵の強化・罠の見破りの決定性・world 統合・step の進行/制覇/ユニーク記録/宝/罠疲労/野営無償/閉域/行動不足/死亡
- **sim:dungeon**（`pnpm sim:dungeon`、thresholds.json `dungeon` 節の受入ゲート）：8世界で迷宮を必ず勝つボットが踏破 —— 全7型が制覇可能・ユニークの生成/討伐記録が世界に1体・1潜り制覇の割合が上限内（1回で抜き切れない深さの定量面）
- e2e（`dungeon.spec.ts`）：門→迷宮の場所→潜る→部屋を抜く→畳んで戻る、野営→眠り→翌日の無償潜り。`scenery.spec.ts` にダンジョン7型を追加
