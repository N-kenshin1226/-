# 05. ロードマップ

> 原則：**どの段階でも遊べる状態を保ち、公開して反応を見る。** ソロの大型開発が途中で止まる典型は、世界生成や遊びを大量に先に作り、肝心の成長が楽しいか分からないまま息切れすること。まず成長の気持ちよさだけを検証する。
> 最大のリスクはオーナーの燃え尽き。M1は **6〜8週** で公開できる大きさに抑える。

## マイルストーン

| M | 内容 | 公開 |
|---|---|---|
| **M0** | 成長コア（経験式・定着・追い風・疲労）＋ **バランスCIゲート**（`sim:growth` / `sim:retention`）＋ CLI版 | ― |
| **M1** | CT戦闘、ミニゲーム3種（**鍛冶・採掘・交渉**、3エンジン）、作品台帳、街1つ＋周辺2エリア、称号20個、起床ログ、通知予算、立場3段階×職業2つ、Web UI | **α版をitch.ioで公開** |
| **M2** | 錆・素質・書物・師匠、派生スキル、ミニゲームを+3（演奏・釣り・鑑定などの別の皮）、新聞・NPCの台詞差分、人生目標カタログ | β版 |
| **M3** | 寿命・伝記・年代記（別領域に保存）、継承（3項目）、転生、頂点ルート2本、前世の伝説（最小版） | 1.0 |
| **M4** | 無限深層、ユニークとの再戦、図鑑、誓約、運命の傾向、ライバル・ランキング、子や弟子への継承 | 以降は継続的に追加 |

### 削ったもの・後回しにしたもの（会議の結論）
- 世界の歴史のシード生成 → 手作りの世界1つ＋出現抽選だけをシード化する
- ライバル冒険者のシミュレーション → ランキングの数値は乱数、噂はテンプレート
- 新聞が世界の状態を変えること → 1行のテンプレート出力だけ（状態は持たない）
- 部位別の疲労 → 疲労は1本
- 本格的なアクション → 3秒の一点勝負だけ

## M0のDevinタスク

各タスクは `04_tech_and_devin.md` §3 のテンプレートで渡す。

| ID | タスク | 主な受け入れ基準 |
|---|---|---|
| T-01 | pnpm monorepoの雛形（core / content / sim / web）、ESLint、Prettier、Vitest、`pnpm check`、GitHub Actions | CIが緑になる |
| T-02 | シード付きPRNG（`rng/`） | 同じシードで同じ列。`fork(label)` は互いに独立した列 |
| T-03 | ゲーム内時間・暦・月齢（`time/`）、1日＝行動回数制 | 境界値のテスト |
| T-04 | `GameState`、`step()`、`ActionEvent` バス、セーブのバージョン | JSONで往復できる |
| T-05 | 経験獲得式（02 §2）：逆U字の挑戦係数、新規性、逓減 | 曲線の各点のテスト。数値はbalance.json |
| T-06 | 定着・持ち越し・睡眠の質（2要因）・起床ログのデータ（02 §3） | 表示順（小さい順＋予想外の1行）のテスト |
| T-07 | 今日の追い風（02 §4） | 偏った行動に逆風が出やすいことのテスト |
| T-08 | 疲労・基礎能力・オーバーワーク（02 §5） | 負荷 → 睡眠 → 上昇のテスト |
| T-09 | **バランスCIゲート**：4種のボット、`sim:growth`・`sim:retention`、02 §10 の指標 | 基準を割るとCIが落ちる |
| T-10 | 条件DSLの評価器と称号のzodスキーマ（03 §7） | すべての演算のテスト、到達可能性の検査 |
| T-11 | CLI版（`pnpm play:cli`）：街 → 訓練・戦闘の代用 → 宿で寝る → 起床ログ | 人間が手で3日分遊べる |

> **M0が終わったら、一度CLIで遊んで「起床ログが気持ちいいか」を判断する。** ここが楽しくなければ、M1に進まず数式を直す。

## M1の主なタスク（概要）
- T-12 `MiniGame<Input,Result>` の型と3エンジン（タイミング／盤面／駆け引き）
- T-13〜15 鍛冶・採掘・交渉（各エンジンの皮）＋簡易判定
- T-16 作品台帳とティア更新の判定
- T-17 CT戦闘のコア（予兆3行、観察で精度が上がる）
- T-18 通知予算（S/A/B）と気配の一行
- T-19 立場×職業と認定の条件
- T-19b 物語：アトムのzodスキーマ、正史 `canon.json` の型、`pnpm lore:check`（参照・事実・文体・重複の検証）、見聞録とつながりの報酬（`07_story.md`）
- T-19c `pnpm lore:gen`（Gemini 3.8 Flash の構造化出力で下書きを生成。APIキーは環境変数から読み、リポジトリに入れない）
- T-20〜 Web UI（ステータス・起床ログ・ミニゲーム・戦闘・宿）。**スタイルガイドを人間が先に渡す**

## 人間（あなた）がやること
- 5本柱とのズレをPRで確認する
- スタイルガイドとUIのラフ（M1の前まで）
- 世界観・固有名詞・文体（システムメッセージ、新聞、NPCの口調）
- **正史 `canon.json` と文体ガイド `style.md` を書く。** 核になるNPCと出来事の物語をレビューする
- **ミニゲームの手触りを触って、数値で返す**
- 遊んで「楽しいか」を判断する。これはDevinにはできない
