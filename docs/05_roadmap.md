# 05. ロードマップ

## MVP（「最初の街の1週間」）の定義

**遊べること**
- 開始の街1つ＋周辺の3エリア（森・洞窟・廃村）＋ユニークシナリオ1本＋ユニークモンスター1体
- スキル12種（剣術・短剣・弓術・投擲・回避・防御・観察・隠密・胆力・採集・鍛冶・料理）＋基礎能力6種
- 使用型成長、睡眠による定着、疲労、素質、錆
- CT制戦闘と予兆。敵8種
- 称号20個、派生スキル3個、隠し職業1つ
- 世界初の台帳、ワールドアナウンス、NPC冒険者100人（ネームド3人）、掲示板（テンプレート生成）
- セーブとロード（IndexedDB＋エクスポート）

**成功の判定**：自分が1週間（ゲーム内7日）遊んで、§「体験として目指す瞬間」（01_concept.md §5）のうち4つ以上が起きる

## フェーズ

| Phase | 内容 | 主担当 |
|---|---|---|
| 0 | リポジトリ雛形・CI・`AGENTS.md`・スタイルガイド | 人間＋Devin |
| 1 | 成長エンジン（ヘッドレス）＋バランスシミュレータ | Devin |
| 2 | 戦闘エンジン（ヘッドレス）＋CLIで遊べる版 | Devin |
| 3 | Web UI（ステータス・ログ・戦闘・宿） | Devin（デザインは人間） |
| 4 | 世界生成・探索・条件付き出現 | Devin |
| 5 | 称号DSL・台帳・NPC冒険者・掲示板 | Devin |
| 6 | MVPのコンテンツ投入・調整・itch.ioで公開 | 人間＋Devin |
| 7以降 | 地方の追加、2Dマップ、製作の深化、PWA、LLMオプション | — |

> **Phase 1〜2はUIなしで先に完成させる**のが最重要。ロジックが固まっていれば、Devinはテストで自走できる。

## Devinタスク一覧（最初の12本）

各タスクは `04_tech_and_devin.md` §3 のテンプレートで渡す。

| ID | タスク | 主な受け入れ基準 |
|---|---|---|
| T-01 | pnpm monorepo雛形（core / content / sim / web）、ESLint、Prettier、Vitest、`pnpm check`、GitHub Actions | 空のテストが通り、CIが緑になる |
| T-02 | シード付きPRNG（`rng/`）。`next()`、`int()`、`pick()`、`fork(label)` | 同じシードで同じ列を返す。`fork` は互いに独立した列になる |
| T-03 | ゲーム内時間と暦（`time/`）：tick・時刻帯・曜日・季節・月齢 | 境界値のテスト（日またぎ・新月） |
| T-04 | `GameState` の型・`step()` の骨格・`ActionEvent` バス | コマンドを流すとイベントが出る。状態はJSONで往復できる |
| T-05 | 経験獲得式（02 §2）：`B×C(Δ)×N×P×F×M`、逓減 | 曲線の各点のテスト。数値はbalance.jsonから読む |
| T-06 | 定着・持ち越し・死線ボーナス（02 §3） | 睡眠の質ごとのテスト。起床ログのデータを生成する |
| T-07 | 素質・錆・脳の容量（02 §5〜6） | 下限70%、再習得×3のテスト |
| T-08 | 基礎能力の負荷成長とオーバーワーク（02 §4） | 負荷 → 睡眠 → 上昇のテスト |
| T-09 | バランスシミュレータ `pnpm sim:growth`（4つの方針のボット、CSVを出力） | 02 §10 の受け入れ基準3つを満たす（満たさない場合はbalance.jsonの調整案を報告） |
| T-10 | 条件DSLの評価器（03 §3） | すべての演算のテスト。称号定義をzodで検証する |
| T-11 | CT制戦闘のコア（03 §2）：CT、予兆、観察による解像度、部位 | 固定シードで戦闘ログのスナップショットテスト |
| T-12 | CLI版の遊べるプロトタイプ（`pnpm play:cli`）：街 → 森で戦う → 宿で寝る → 起床ログ | 人間が手で1日分遊べる |

> T-12まで終わったら、**一度自分で遊んで「楽しいか」を判断する**。ここで手触りが悪ければ、UIを作る前に数式を直す。

## 人間（あなた）がやること
