# 07. ストーリー：小さな物語のネットワーク

## 1. 方針

- **大きな一本道のメインストーリーは置かない。** 世界の秘密を一つ暴くような縦糸も置かない
- 代わりに、**物・場所・NPC一つひとつに小さな物語**を付ける
- 小さな物語同士が、人物・出来事・時代を介して**つながっている**。プレイヤーが拾い集めるうちに、つながりから大きな絵が浮かび上がる
- 参考になるゲーム：
  - ダークソウル／エルデンリング：アイテム説明文の断片から歴史が見える
  - Stardew Valley：住人ごとの段階的な個別イベント
  - Outer Wilds：知識そのものが進行の鍵になる

## 2. 物語の単位（ストーリー・アトム）

| 種類 | 例 | 量の目安（MVP） |
|---|---|---|
| **物** | 武器・道具・書物・遺品の説明文。手に入れた経緯で一文が変わる | 60 |
| **場所** | 廃村、橋、墓、鍛冶場の由来。調べると1〜3段階で深まる | 20 |
| **NPC** | 住人ごとの個人的な物語（3〜5段階）。条件・時期・プレイヤーの選択で展開と結末が変わる | 12人 |
| **出来事** | 過去の事件（戦、疫病、大火、ある職人の失踪）。直接は描かず、物・場所・NPCの断片から間接的に見える | 8 |

### アトムのデータ形式

```jsonc
{
  "id": "item.rusted_hammer",
  "kind": "item",
  "title": "錆びた槌",
  "text": "柄に〈ベルナ〉と刻まれている。打面だけが妙に磨かれている。",
  "refs": ["npc.berna", "event.great_fire", "place.old_forge"], // つながり先（正史の要素ID）
  "reveals": ["fact.berna_survived_fire"],                       // 読むと分かる事実
  "reliability": "fact",       // fact（事実）／ rumor（噂：間違っていてもよい）
  "unlock": { "flag": "found.old_forge.cellar" }
}
```

## 3. つながりの仕組み（遊びに効かせる）

- **見聞録**：読んだアトムと分かった事実が記録される。共通の参照先を持つアトム同士は、線でつながって見える
- **つながりの報酬**：ある出来事に関わる事実が一定数集まると、次のものが開く
  - 隠しの依頼やユニークシナリオ（例：大火の真相を知ると、生き延びた職人ベルナの居場所が分かる）
  - NPCの物語の分岐（真相を知っていると選べる選択肢が増える）
  - 派生スキルや称号の条件（「知識と腕が効く」の「知識」の部分）
- **噂は間違っていてもよい**：`rumor` のアトムは事実と食い違ってかまわない。食い違いそのものが手がかりになり、矛盾が「味」になる
- **プレイヤーの物語もアトムになる**：作品台帳の名品や年代記の偉業には、自動で説明文が付く。次の周回では、前世の作品が「物」のアトムとして世界に現れる（06_endgame.md の遺物）
- **NPCも年を取る**：一生の間に、NPCの物語は進んだり終わったりする（引退、結婚、死）。結末は年代記に残る

## 4. 正史（ワールドバイブル）

つながりを破綻させないための、唯一の正しい設定集。**人間（オーナー）が書く。** 短くてよい。

```
packages/content/lore/
├─ canon.json      # 正史：時代・出来事・人物・場所・勢力と、確定した事実（fact）の一覧
├─ atoms/*.json    # アトム（生成または手書き）
└─ style.md        # 文体ガイド（語彙、文の長さ、禁止表現、例文）
```

- アトムが参照できるのは、`canon.json` にあるIDだけ
- `fact` として断言できるのは、正史の事実だけ。それ以外は `rumor` にする

## 5. LLMの役割分担と生成パイプライン

### 役割分担

| 作業 | 担当 | 理由 |
|---|---|---|
| 正史・文体ガイドの下書き、核になるNPCと出来事の物語 | **Claude Opus 5.5** → オーナーが仕上げる | 文章の質と、設定の一貫性が最も重要な部分 |
| アトム（物・場所・NPC）の執筆 | **Claude Opus 5.5**（Claude Codeのセッションで、`canon.json` と `style.md` を読んでアトムのJSONを直接書く） | 質を優先する。量は型ごとに少しずつ |
| コード（ゲーム本体、`lore:check` などのツール） | **Devin（SWE-2）** | 実装・テスト |
| **APIとして組み込む用途だけ** | **Gemini 3.8 Flash**（`gemini-3.8-flash`） | プログラムから呼ぶ処理（下記） |

### Gemini APIの用途
- スクリプトから大量に回す、質より量の処理：NPCの台詞の言い換え差分、新聞の見出しテンプレートの変種、称号のフレーバー文の候補
- `pnpm lore:gen --provider gemini` として呼び出す。構造化出力（JSON Schema）を使い、アトムのzodスキーマから生成したスキーマを渡す
- 料金：100万トークンあたり入力$0.75／出力$3.75（2026年12月31日まで。2027年1月から倍）。無料枠あり
- **プレイ中に呼ぶ（実行時の機能）かどうかは未決**。呼ぶ場合はサーバー経由（Cloudflare Workers）にし、APIキーを隠し、利用量の上限を付ける。規約の確認が前提（下記）

### 検証の流れ（どの担当が書いても同じ）

```
下書きアトム（atoms/_draft/*.json）  ← Opus 5.5 または Gemini API
   ↓ 自動検証（pnpm lore:check）
   │  ├ zodスキーマ（Geminiは文字数などの一部の制約を無視するので、必ずこちらで検証する）
   │  ├ 参照IDが正史に存在するか
   │  ├ fact が正史の事実と一致するか
   │  ├ 文体のlint（禁止語、文の長さ、システムメッセージの書式）
   │  └ 似た文の重複検出
   ↓ 人間のレビュー（全件は不要。核になるNPCと出来事は必ず読む）
atoms/*.json としてコミット
```

- 生成は**型ごとに少量ずつ**行う。大量に一度に作ると、似た文ばかりになる

### 規約上の注意（Gemini API利用規約、2026-10時点の要約）
- 生成物の所有権はGoogleが主張しない。利用の責任は利用者にある
- **無料枠では、入出力がGoogleのモデル改善に使われる。** 公開するゲームのテキストなら実害は小さいが、気になるなら有料枠を使う（有料枠は学習に使われない）
- 「18歳未満が利用しうるクライアントでの利用」や「消費者向け」に関する制限がある。**開発時のスクリプトから呼ぶだけなら問題は避けやすいが、プレイ中に呼ぶ機能を作る場合は、条文を原典で必ず確認する**（https://ai.google.dev/gemini-api/terms）

## 6. MVP（M1）で入れる範囲
- 正史：開始の街と周辺2エリアに関わる出来事3つ、人物10人
- アトム：物30、場所10、NPC5人（各3段階）
- 見聞録と、つながりの報酬1つ（隠しの依頼）
