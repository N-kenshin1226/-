# 07. ストーリー：小さな物語のネットワーク

## 1. 方針

- **大きな一本道のメインストーリーは置かない。** 世界の秘密を一つ暴くような縦糸も置かない
- 代わりに、**物・場所・NPC一つひとつに小さな物語**を付ける
- 小さな物語同士が、人物・出来事・時代を介して**つながっている**。プレイヤーが拾い集めるうちに、つながりから大きな絵が浮かび上がる
- 参考になるゲーム：
  - ダークソウル／エルデンリング：アイテム説明文の断片から歴史が見える
  - Stardew Valley：住人ごとの段階的な個別イベント
  - Outer Wilds：知識そのものが進行の鍵になる

## 2. 物語の単位（ストーリー・アトム）

| 種類 | 例 | 量の目安（MVP） |
|---|---|---|
| **物** | 武器・道具・書物・遺品の説明文。手に入れた経緯で一文が変わる | 60 |
| **場所** | 廃村、橋、墓、鍛冶場の由来。調べると1〜3段階で深まる | 20 |
| **NPC** | 住人ごとの個人的な物語（3〜5段階）。条件・時期・プレイヤーの選択で展開と結末が変わる | 12人 |
| **出来事** | 過去の事件（戦、疫病、大火、ある職人の失踪）。直接は描かず、物・場所・NPCの断片から間接的に見える | 8 |

### アトムのデータ形式

```jsonc
{
  "id": "item.rusted_hammer",
  "kind": "item",
  "title": "錆びた槌",
  "text": "柄に〈ベルナ〉と刻まれている。打面だけが妙に磨かれている。",
  "refs": ["npc.berna", "event.great_fire", "place.old_forge"], // つながり先（正史の要素ID）
  "reveals": ["fact.berna_survived_fire"],                       // 読むと分かる事実
  "reliability": "fact",       // fact（事実）／ rumor（噂：間違っていてもよい）
  "unlock": { "flag": "found.old_forge.cellar" },
  "visible": { "counter": "landmark.found.lm.x", "gte": 1 } // 省略可。見聞録の一覧に出る条件（X-33）
}
```

- `visible`（省略可）は見聞録の一覧に頁が現れる条件。立つまで名も出ない ——
  名所の頁のように「その場を踏んで初めて存在を知る」アトムに使う

## 3. つながりの仕組み（遊びに効かせる）

- **見聞録**：読んだアトムと分かった事実が記録される。共通の参照先を持つアトム同士は、線でつながって見える
- **つながりの報酬**：ある出来事に関わる事実が一定数集まると、次のものが開く
  - 隠しの依頼やユニークシナリオ（例：大火の真相を知ると、生き延びた職人ベルナの居場所が分かる）
  - NPCの物語の分岐（真相を知っていると選べる選択肢が増える）
  - 派生スキルや称号の条件（「知識と腕が効く」の「知識」の部分）
- **噂は間違っていてもよい**：`rumor` のアトムは事実と食い違ってかまわない。食い違いそのものが手がかりになり、矛盾が「味」になる
- **プレイヤーの物語もアトムになる**：作品台帳の名品や年代記の偉業には、自動で説明文が付く。次の周回では、前世の作品が「物」のアトムとして世界に現れる（06_endgame.md の遺物）
- **NPCも年を取る**：一生の間に、NPCの物語は進んだり終わったりする（引退、結婚、死）。結末は年代記に残る

## 4. 正史（ワールドバイブル）

つながりを破綻させないための、唯一の正しい設定集。**人間（オーナー）が書く。** 短くてよい。

```
packages/content/lore/
├─ canon.json      # 正史：時代・出来事・人物・場所・勢力と、確定した事実（fact）の一覧
├─ atoms/*.json    # アトム（生成または手書き）
└─ style.md        # 文体ガイド（語彙、文の長さ、禁止表現、例文）
```

- アトムが参照できるのは、`canon.json` にあるIDだけ
- `fact` として断言できるのは、正史の事実だけ。それ以外は `rumor` にする

## 5. LLMの役割分担と生成パイプライン

### 役割分担

| 作業 | 担当 | 理由 |
|---|---|---|
| 正史・文体ガイドの下書き、核になるNPCと出来事の物語 | **Claude Opus 5.5** → オーナーが仕上げる | 文章の質と、設定の一貫性が最も重要な部分 |
| アトム（物・場所・NPC）の執筆 | **Claude Opus 5.5**（Claude Codeのセッションで、`canon.json` と `style.md` を読んでアトムのJSONを直接書く） | 質を優先する。量は型ごとに少しずつ |
| コード（ゲーム本体、`lore:check` などのツール） | **Devin（SWE-2）** | 実装・テスト |
| プレイ中の語り（実行時） | **未決**（候補：Gemini 3.8 Flash ほか。§6） | 規約の確認が前提 |

### 検証の流れ（どの担当が書いても同じ）

```
下書きアトム（atoms/_draft/*.json）  ← Opus 5.5
   ↓ 自動検証（pnpm lore:check）
   │  ├ zodスキーマ（Geminiは文字数などの一部の制約を無視するので、必ずこちらで検証する）
   │  ├ 参照IDが正史に存在するか
   │  ├ fact が正史の事実と一致するか
   │  ├ 文体のlint（禁止語、文の長さ、システムメッセージの書式）
   │  ├ 似た文の重複検出
   │  └ つながりの到達性（報酬に要る事実は公開＋隠しアトムのどれかが明かす。源がなければ error）
   ↓ 公開範囲のアトムだけ人間が確認する（隠しの内容は読まない。下記）
atoms/*.json としてコミット
```

### ネタバレ防止（自分で遊ぶための開発体制）
作り手が自分で遊ぶと、隠し条件も物語の結末も知っていて驚きがなくなる。そこで、**オーナーが知る範囲を意図的に絞る**。
- オーナーが書くのは正史の骨格（時代・大きな出来事・主要人物の名前）と文体ガイドだけ
- アトムの細部、隠し条件、派生スキルの条件、NPCの物語の結末は Opus 5.5 が書く。オーナーは読まない
- 品質は自動検証（`lore:check`、到達可能性の検査、`sim:retention`）で担保する。Devinへのタスクでも、隠しの内容をPRの説明に書かせない
- `packages/content/hidden/` に隔離し、エディタや差分表示でうっかり見ないようにする

- 生成は**型ごとに少量ずつ**行う。大量に一度に作ると、似た文ばかりになる

## 6. 実行時の語り層（プレイ中にLLMを呼ぶ）

プレイヤー固有の出来事を、その場で文章にする。**手書きやテンプレートでは作れない「自分だけの物語」**が狙い。

### 使い所
| 場面 | 入力（構造化データだけを渡す） | 呼び出しの頻度 |
|---|---|---|
| 朝の新聞・噂 | 前日の行動ログ、作品台帳、世界の出来事 | 睡眠時に1回（まとめて生成） |
| NPCの一言 | NPCの設定、プレイヤーとの関係、プレイヤーの経歴の要約 | 会話時。結果はセーブにキャッシュする |
| 見聞録のまとめ | つながったアトムと事実 | つながりが増えたとき |
| 伝記 | 一生の年代記 | 引退・死亡時に1回 |

### ルール
- **LLMは文章を書くだけ。ゲームの結果（成否・数値・分岐）は決めない。** 結果は `core` が先に決め、LLMはそれを語る
- 入力は正史と台帳の構造化データだけ。出力は検証する（長さ、禁止語、システムメッセージの書式）。正史にない内容は、すべて「噂」扱いにする
- 生成した文章はセーブに保存する。同じ場面で毎回呼ばない
- **テンプレートによる代替を必ず用意する。** オフライン、上限超過、APIの障害でもゲームは普通に遊べる
- プレイヤーの自由入力は送らない（M4以降に検討。プロンプトインジェクションと不適切な出力のリスクがある）
- 実装は `NarrationProvider` インターフェースで差し替え可能にする：`TemplateProvider`（標準）／`ApiProvider`（サーバー経由）／`LocalProvider`（ブラウザ内LLM。将来の候補）
- APIはCloudflare Workers経由で呼び、APIキーは隠す。プレイヤーごと・1日ごとの呼び出し上限を付ける

### 費用の目安（Gemini 3.8 Flash の場合の概算）
- 1時間あたり約4回の呼び出し（入力2,000トークン、出力400トークン）として、1人1時間あたり約$0.012（2027年からは約$0.024）
- 月1,000人が10時間ずつ遊ぶと、月$120〜240程度。上限とキャッシュで抑える

### 規約上の問題（**未解決・要確認**）
Gemini API利用規約（https://ai.google.dev/gemini-api/terms 、2026-10-25取得）には、次の記載がある。
- "You must be 18 years of age or older to use the APIs."
- "You also will not use the Services as part of a website, application, or other service ... that is directed towards or is likely to be accessed by individuals under the age of 18."
- "Use of Google AI Studio and Gemini API is for developers building with Google AI models for professional or business purposes, not for consumer use."
- EEA・スイス・英国のユーザーに提供する場合は、有料のサービス（Paid Services）しか使えない

→ **自分だけで遊ぶ間は Gemini 3.8 Flash を使う**（API利用者である本人が18歳以上であることが規約の前提）。費用は月数ドル以下の見込み。
→ **公開する場合**、未成年も遊べる無料の公開ブラウザゲームで実行時にGeminiを使うのは、規約に抵触する可能性が高い。そのときは次のどれかを選ぶ。
1. Geminiを使い、ゲームを18歳以上限定にする（年齢確認を入れても「未成年がアクセスしうる」に当たる可能性は残る）
2. 一般消費者向けアプリでの利用を規約で認めている、別のAPIプロバイダーを使う（各社の規約を要調査）
3. ブラウザ内LLM（Chromeの組み込みAI、WebLLMなど）を使う。費用はかからないが、対応端末が限られ、品質も低め
4. 実行時の語りはオプション機能にして、標準はテンプレートで遊べるようにする（1〜3のどれとも組み合わせられる）

## 7. MVP（M1）で入れる範囲
- 正史：開始の街と周辺2エリアに関わる出来事3つ、人物10人
- アトム：物30、場所10、NPC5人（各3段階）
- 見聞録と、つながりの報酬1つ（隠しの依頼）
- `NarrationProvider` の型と `TemplateProvider` だけ。実行時のLLMはプロバイダー決定後（M2以降）
