## タスク: [R-01] リアルな揺らぎ（ランダム性）

### 問題
- 同じことをすると同じ結果になり、リアルさがない

### 方針
- 現実のように**結果に幅がある**ようにする。ただし主人公だけが得をする・損をする乱数にはしない（**主人公は運も良くも悪くもない**。乱数は誰にでも同じように働く）
- 理不尽にしない：幅は「技量が高いほど安定する」形にする。低技量はブレが大きく、高技量は安定する

### やること
1. **成長の揺らぎ**：同じ行動でも得る経験に幅（±の分布）。まれに「今日は妙に冴えている」大きな伸び（起床ログで分かる）
2. **戦闘の揺らぎ**：与ダメージ・被ダメージに幅、会心・痛恨、敵ごとの個体差（同じ狼でも強い個体・臆病な個体）
3. **仕事・ミニゲームの揺らぎ**：素材の質のばらつき、客の気分、思わぬ出来栄え（会心作・失敗作）
4. **経済の揺らぎ**：相場が日ごと・季節ごとに動く。豊作・不作・品薄
5. **人の揺らぎ**：NPCの機嫌・予定・体調。会えない日もある
6. **体調の揺らぎ**：起きたときの調子（好調・普通・不調）。睡眠・食事・疲労で傾く
7. 揺らぎの大きさは種類ごとに balance.json で調整できるようにする

### 受け入れ基準
- [ ] 同じシード・同じ入力なら同じ結果（決定論は保つ）
- [ ] 異なるシードでは、同じ行動の結果に分布がある（テストで分散を確認）
- [ ] 技量が高いほど結果の分散が小さい（テスト）
- [ ] 乱数が主人公だけに有利／不利になっていない（主人公とNPCで同じ分布を使うことをテスト）

### 共通
- 背景：オーナーが遊んだ感想 **「ランダム性がなければリアルじゃない」「音も欲しい」「行動の種類が少ない」「画面転換がない」**。このタスクはその解消が目的
- `docs/design/` の見た目のルールを守る。新しい場所の背景は、デザイン見本と同じ作り（SVGの情景レイヤー）で描く
- 乱数はすべてシード付きRNG（`rng/`）で。テストとsimは決定論的に保つ
- 数値は balance.json / theme.ts に置き、オーナーが調整できるようにする
- バランスCIゲートが落ちる場合は、閾値ではなく数値で合わせる
- PRに、変更前と変更後のスクリーンショットを添付する
