## タスク: [T-09] バランスCIゲート

### 目的
**Devinの変更が静かにゲームを壊すのを防ぐ、唯一の機械的な手段。** 方針の違うボットに遊ばせて、成長と飽きの指標を自動で判定する。

### 読むもの
**`docs/02_growth_system.md` §10（必読。指標と合格条件はここが正）**、`docs/03_world_systems.md` §6（新規性の供給スケジュール）

### 作るもの（`packages/sim/`）
- ボット4種：単一ルーチン型（その時点で gain 最大の行動を毎回選ぶ）、多様型、ランダム型、簡易判定のみ型（M0ではミニゲームが無いので、訓練のみで代用し、PRの判断ログに書く）
- 実時間の換算：1行動 ＝ 3分（balance.json の `sim.minutesPerAction`）
- `pnpm sim:growth`：各ボットで標準60日分を回し、スキル推移をCSV（`packages/sim/out/`、gitignore）と要約表で出す
- `pnpm sim:retention`：15分・1時間・3時間・8時間の各時間帯の「初体験イベント」（初めての称号、初めてのランクアップ、初めての追い風の種類など）の件数と、同一行動の最大連続回数を出す
- 合格条件は `packages/sim/thresholds.json` に置き、**割ったら非ゼロで終了**する。`pnpm check` から両方を呼ぶ
- 合格条件の値は 02 §10 のとおり。M0で満たせない指標（ミニゲームが前提のもの）は `"enabled": false` にして理由を書く

### 受け入れ基準
- [ ] 同じシードで同じ結果になる
- [ ] 意図的に balance.json を壊すと（例：挑戦係数を平坦にする）、CIが落ちることを確認した（確認後は戻す）
- [ ] 現在の balance.json で全指標が合格する。**合格しない場合は、thresholds を緩めずに balance.json の調整で合わせる**。どうしても合わない場合は blocked にして、指標ごとの実測値をPRに書く
- [ ] 実行時間が CI で 2分以内

### 共通
- `AGENTS.md` の「絶対ルール」と「完了の定義」を守る
- ゲームの数値は `packages/content/balance.json` に置き、zodスキーマ（`balance.schema.ts`）も更新する
- 乱数を使うテストはシードを固定する
- PRの説明に「判断ログ」節を設け、仕様にない判断を1行ずつ書く
