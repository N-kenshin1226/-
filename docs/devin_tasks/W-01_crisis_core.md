## タスク: [W-01] 危機の筋書きと世界の備え

### やること（仕様 §3・§4）
- `packages/content/crises/schema.ts`：危機の型のzodスキーマ（段階、段階ごとの影響、勢力、決着の場面、接点、語りの参照、重さの出現率）
- `packages/content/crises/sample.json`：テスト用の公開サンプル1つ
- 世界の作成時に、シードから危機を1つ抽選し、変数を決める。`hidden/crises/*.json` があればそれを、なければ sample を使う
- 季節の変わり目に段階を進め、影響をゲーム状態に反映する（エリア、物価、NPCの離散・死亡、敵の強さ、危機の中でだけ出る依頼・素材）
- 勢力が季節ごとに5分野の**備え**を積む
- **決着の場面**：筋書きの時期に、その時点の備えで成否を判定する（乱数は控えめ）。全部終わったら終幕（解決／滅び）
- セーブのバージョンを上げ、移行関数を書く（既存のセーブは次の季節に危機を抽選）

### 受け入れ基準
- [ ] 同じシードで同じ危機・変数になる。シードを変えると変わる
- [ ] 段階の進行・影響の適用と解除・備えの蓄積・決着の判定のテスト
- [ ] 主人公が何もしなくても、サンプルの危機が決着まで進むテスト

### 共通
- 仕様は **`docs/08_world_crisis.md`** が正。`AGENTS.md` の絶対ルールと完了の定義を守る
- **世界を主人公に背負わせない**（仕様 §1）。危機を主人公向けのクエストや「やるべきこと」の一覧として見せない。接点は断っても不利益なし
- 数値は `balance.json`、データは zod スキーマ付きの JSON
- テストは公開サンプル（`packages/content/crises/sample.json`）で書く。**`packages/content/hidden/` の中身を読んだり、PRの説明・コミットメッセージ・報告に書いたりしない**（読み込む仕組みだけ作る）
- PRの説明に「判断ログ」節
