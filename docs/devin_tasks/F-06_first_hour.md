## タスク: [F-06] 最初の1時間を整える＋不具合

### やること
1. **1周目の開始画面に「誓約」「運命の傾向」を出さない**。1周目は名前と出自だけで始める。2周目以降（年代記が1件以上あるとき）だけ表示する
2. 開始直後に、短い導入（どこにいて、何ができて、寝ると成長する）を会話の窓で1〜2画面だけ
3. 最初の15分以内に「称号」「勝負所」「起床ログの成長」を一度ずつ体験できるよう、序盤の注文と出来事を調整する
4. **不具合**：戦闘の勝利時に `――{name} を倒した。` とテンプレートの置換漏れが出る。テキストのテンプレートで置換漏れがないかを検査するテストを追加する（`{` が残った文を出したら失敗）

### 受け入れ基準
- [x] 1周目の開始画面に誓約・運命の傾向が出ない（e2e：first-hour.spec.ts）
- [x] 置換漏れ検査のテストがあり、通る（apps/web/src/text-templates.test.ts）

### 判断ログ（実装メモ）
- **開始画面**：`screens/title.tsx` で `loadChronicle().lives.length === 0` のとき出自の列だけにした。2周目以降は「選ばなくても始められる」→ 傾向 → 誓約の順で従来どおり
- **導入**：`screens/intro.tsx`（会話窓・宿屋の主マルタ・2頁）。`startNew` で年代記が空のときだけ挟む。Enterで進む／Esc・クリックで飛ばせる。転生・次代（born/heirBorn）経路では出さない ―― 始め方を知っている生には不要
- **15分体験**：称号（初仕事）と起床ログの成長は既存の仕組みで初日に届くことを確認済み。届いていなかったのは「勝負所」だけ ―― 既存の行事はすべて技能・実績の条件つきで新顔には届かない。day===0 のコード条件は書かず、コンテンツ側に `debut.inn_recital`（宿場の披露目。0〜3日目に届く・演技ミニゲーム・目標品質20・敗北ペナルなし）を occasions.json に追加した。デフォルトの再提示間隔（6日）より窓（4日）が狭いので1生に1度だけ届く。`offerChance` は日ごとの抽選なので必ず届くわけではない（約94%）――完全保証にしたいなら balance の調整が要るが、それは F-05 管轄なので要確認とする
- **置換漏れ**：hunt.tsx の勝利文3箇所（occasion/決着/通常戦闘の各finish経路）と work.tsx の盤面ミニゲーム開始文（miningStart/appraisalStart が `{name}` 素出し）を修正。`text-templates.test.ts` は (a) 表示用コンテンツ全JSONを tpl 相当で描画して生の `{` `}` が残らないこと、(b) `{` を含む `t.text.*` が tpl() 外で使われていないことを AST で検査する
- 既存e2eは開始直後にメニューを期待するため、導入を読み進める `skipIntro` ヘルパー（e2e/helpers.ts）を全specに適用した

### 共通
- 背景：オーナーが実際に遊んだ感想は **「刺激があんまりない」**。このタスクの目的は、それを直すこと。仕様の細部より「遊んで気持ちいいか」を優先してよい（変えた点は判断ログに書く）
- `docs/design/` の見た目のルールを守る。演出の数値（時間・大きさ・音量など）は theme.ts か balance.json に置き、オーナーが調整できるようにする
- バランスCIゲート（`pnpm sim:*`）が落ちる場合は、閾値ではなく数値で合わせる。仕様の意図とぶつかる場合は判断ログに「要確認」
- PRに、変更前と変更後のスクリーンショット（動きがあるものは数枚の連続画像）を添付する
