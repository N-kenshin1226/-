# 夜間の自走手順

オーナーは寝ていて、**質問には誰も答えない。** 止まらずに最後まで進めること。

## 0. 準備
1. `main` を最新にする
2. `AGENTS.md` と `docs/devin_tasks/QUEUE.md` を読む

## 1. タスクの選び方
- `QUEUE.md` を上から読み、**状態が `todo` で、依存がすべて `done` の最初のタスク**を選ぶ
- そのようなタスクがない、または次が `needs_human` なら、§5 の報告だけ書いて終了する
- **1晩に実行するタスクは最大4本**

## 2. 実装
1. ブランチ `task/<ID>` を作る
2. 依頼文（`docs/devin_tasks/<ID>_*.md`）と、そこで指定された docs の節を読んで実装する
3. 同じブランチで `QUEUE.md` のそのタスクの状態を `done` に変える
4. ローカルで `pnpm check` を通してから push し、PRを作る（タイトルは依頼文の指定どおり）
5. PRの auto-merge（squash）を有効にする

## 3. CIが落ちたら
- 原因を調べて直し、push する。**同じタスクで修正は最大3回まで**
- 3回直しても緑にならない場合：
  - PRはドラフトに戻し、`QUEUE.md` の状態を `blocked` にして備考に理由を1行書く（この変更は別の小さなPR `queue: <ID> blocked` で `main` に入れる）
  - そのタスクに依存するタスクは飛ばし、依存しない次のタスクへ進む
- **テストを消す・無効にする・閾値を緩めることで緑にしてはいけない**（`pnpm sim:*` の基準を含む）

## 4. 判断に迷ったら
- **質問しない。** 最も標準的で、あとから変えやすい選択をする
- 選んだ内容と理由を、PRの説明の「判断ログ」節に1行ずつ書く
- 仕様（`docs/`）と矛盾する、または仕様が足りないと判断したら：仕様は変更せず、最も保守的な実装にして、判断ログに「要確認」と書く
- 次のことは**絶対にしない**：`docs/0*.md`・`AGENTS.md`・このファイルの変更、CIの設定の緩和、ブランチ保護の変更、`main` への直接push、APIキーやシークレットのコミット（このリポジトリは公開されている）

## 5. 朝の報告
最後に `docs/reports/YYYY-MM-DD.md`（日付は日本時間）を書き、PR `report: YYYY-MM-DD` として auto-merge で入れる。

```md
# 夜間レポート YYYY-MM-DD

## 結果
| ID | 状態 | PR | 一言 |
|---|---|---|---|

## オーナーに確認してほしいこと
（「要確認」の判断ログ、blocked の理由。無ければ「なし」）

## 次に実行されるタスク
```

- 報告は短く。**隠し要素（`packages/content/hidden/` の中身、隠し条件、物語の結末）は報告やPRに書かない**
